# AI Planner Module

The `planner` module is the core of the AI-driven functionality in the Project Planner Server. It orchestrates the generation of code modification plans by interacting with Large Language Models (LLMs) and executes these plans safely on a Git repository.

## Services

### `PlannerService` (`src/planner/planner.service.ts`)
The main orchestration service for creating, retrieving, chunking, and applying AI-generated plans.

**Key Responsibilities:**
-   Delegates to `LlmService` for generating plans from user prompts.
-   Validates generated plans using `validator.ts`.
-   Persists plans and their associated file changes to the database.
-   Retrieves plans from the database.
-   Divides large plans into smaller, manageable "chunks."
-   Delegates to `ExecutorService` for applying plans or plan chunks to the codebase.

**Key Methods:**
-   `planFromPrompt(llmInput: LlmInputDto, userId: string)`: Generates a plan using the LLM, validates it, and saves it to the database. Returns the `planId` and the `PlanDto`.
-   `getPlan(planId: string, userId: string)`: Retrieves a plan and its changes from the database by ID.
-   `chunkPlan(planId: string, userId: string, size = 3)`: Splits a plan's file changes into an array of chunks for staged application.
-   `applyChunk(planId: string, chunkIndex: number, userId: string)`: Applies a specific chunk of changes from a plan. This method utilizes `ExecutorService` for the actual file system and Git operations.
-   `applyPlan(plan: PlanDto, userId: string)`: Applies an entire plan at once. This also uses `ExecutorService` and includes validation.

---

### `LlmService` (`src/planner/llm.service.ts`)
Manages communication with various Large Language Models (LLMs) to generate code change plans.

**Key Responsibilities:**
-   Abstracts away the details of interacting with different LLM APIs (Google Gemini, OpenAI).
-   Constructs prompts based on user input, project structure, and relevant file content.
-   Parses LLM responses into a structured `PlanDto`.
-   Provides a mock implementation for testing or when no LLM API keys are configured.

**Key Methods:**
-   `generatePlan(llmInput: LlmInputDto)`: Main method to request a plan from an LLM. Automatically selects between Gemini, OpenAI, or a mock based on configuration.
-   `generatePlanWithOpenAI(llmInput: LlmInputDto)`: Handles API calls and response parsing for OpenAI models.
-   `generatePlanWithGemini(llmInput: LlmInputDto)`: Handles API calls and response parsing for Google Gemini models.
-   `mockPlan(llmInput: LlmInputDto)`: Provides a hardcoded plan for specific prompts, useful for development without actual LLM calls.
-   `static extractJsonFromMarkdown(text: string)`: Utility to extract JSON blocks from LLM responses that might be wrapped in Markdown.

---

### `ExecutorService` (`src/planner/executor.service.ts`)
Responsible for safely applying code changes generated by the LLM to the local Git repository and performing post-application checks.

**Key Responsibilities:**
-   Ensures atomic application of changes by creating a Git snapshot before modifications and rolling back on failure.
-   Directly manipulates the file system (add, modify, delete files).
-   Applies Git patches (`diff`) when provided.
-   Integrates with `GitUtilService` for repository operations (branching, committing, resetting).
-   Runs static analysis tools (TypeScript compiler, ESLint) after applying changes to ensure code quality.

**Key Methods:**
-   `snapshotAndApply(planId: string, changes: FileChangeDto[])`: The core method that takes a list of `FileChangeDto`s, creates a Git branch and snapshot, applies the changes, runs checks, commits, and handles rollbacks.

## Types and DTOs (`src/planner/dto.ts`)

This file defines the Data Transfer Objects (DTOs) used for communication within the planner module and with LLMs.

**Key Types:**
-   `FileChangeDto`: Describes a single file modification (path, action, new content, diff, reason).
-   `CreatePlannerDto`: Represents a complete AI-generated plan, including a title, summary, thought process, and an array of `FileChangeDto`s.
-   `LlmInputDto`: The input structure for the LLM, containing the user prompt, project context, and output format requirements.
-   `ScannedFileDto`: Represents a file's content and path, used to provide context to the LLM.

## Validation (`src/planner/validator.ts`)

-   **`PlanSchema`, `FileChangeSchema`**: Zod schemas used to validate the structure and content of AI-generated plans, ensuring they conform to expected formats before being processed or applied.
-   `validatePlan(obj: unknown)`: A utility function that parses an object against `PlanSchema` and throws a `CustomError` on validation failure.

## API Endpoints (`/api/plan`)

The AI planner module exposes the following endpoints (defined in `src/planner/planner.router.ts`), all requiring authentication:

-   `POST /api/plan`: Initiates the AI planning process based on a user prompt. Returns a new plan.
-   `GET /api/plan/:id`: Retrieves the details of a specific AI plan by its ID.
-   `GET /api/plan/:id/chunks`: Divides a specified plan into manageable chunks of file changes.
-   `POST /api/plan/:id/apply-chunk/:index`: Applies a specific chunk of changes from a plan to the Git repository.
-   `POST /api/plan/apply`: Applies an entire AI plan (all its changes) to the Git repository.
